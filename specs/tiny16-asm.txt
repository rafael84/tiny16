tiny16 Assembler Specification
==============================

SOURCE
------

- One instruction per line
- Case-insensitive
- Leading/trailing whitespace ignored
- Empty lines ignored

PREPROCESSOR
------------

Runs automatically before assembly (Pass 0).

Macros:
    .macro NAME param1, param2, ...
        body
    .endmacro

    NAME arg1, arg2

- Parameters replaced with arguments
- Labels starting with @ are local per invocation
- Format: __MACRONAME_N_labelname

Includes:
    .include "filename"

- Inserts file contents
- Path relative to source file directory
- Max depth: 16

Example:
    .macro LOAD16 dest, hi, lo
        LOADI R6, hi
        LOADI R7, lo
        LOAD dest, [R6:R7]
    .endmacro

    LOAD16 R0, 0xBF, 0x22

COMMENTS
--------

- `;` starts a comment
- Everything after `;` is ignored

LABELS
------

- Defined as `name:`
- Refer to the address of the next instruction
- Must be unique

CONSTANTS
---------

- Syntax: `NAME = expression`
- Value must be 0..65535
- Shares namespace with labels (no duplicates)
- Can use expressions (see EXPRESSIONS)

REGISTERS
---------

- R0–R7
- Case-insensitive
- R6:R7 form ADDR for indirect memory access
- Assembler does not encode ADDR explicitly

NUMBERS
-------

- Decimal: 42, Hex: 0x2A, Binary: 0b101010
- Range: 0..65535 for 16-bit values, 0..255 for 8-bit values

EXPRESSIONS
-----------

Expressions are supported in:
- Constants (NAME = expression)
- Immediate values (LOADI, JMP, CALL, etc.)
- Directive arguments (ORG, TIMES)

Operators (precedence: high to low):
    -expr  ~expr           Unary minus, bitwise NOT
    * / %                  Multiply, divide, modulo
    + -                    Add, subtract
    << >>                  Shift left, right
    &                      Bitwise AND
    ^                      Bitwise XOR
    |                      Bitwise OR
    (expr)                 Parentheses

Symbols (labels and constants) can be used in expressions.

Examples:
    SIZE = 8 * 8 / 2                ; Constant: 32
    MASK = (1 << 4) | 0x0F          ; Constant: 0x1F
    LOADI R0, 5 + 3 * 2             ; Immediate: 11 (precedence: * before +)
    LOADI R1, (5 + 3) * 2           ; Immediate: 16
    ORG 0x4000 + 256                ; Directive argument

    ; Common pattern: splitting 16-bit addresses
    ADDR = 0x4020
    LOADI R6, ADDR >> 8             ; High byte: 0x40
    LOADI R7, ADDR & 0xFF           ; Low byte: 0x20

SECTIONS
--------

- section .code : instructions go here
- section .data : data definitions go here
- Default section is .code if not specified
- Labels in each section resolve to their respective memory addresses

PSEUDO-INSTRUCTIONS
-------------------

ORG (Set Origin)
    - Syntax: ORG addr16
    - .data only
    - Sets the data location counter to addr16:
        - If addr16 > current: pad with 0x00 up to addr16
        - If addr16 < current: error (no rewinding/overwrites)
    - addr16 can be a number or expression, must evaluate to 0x4000..0x923F

TIMES (Repeat)
    - Works in both .code and .data sections
    - Syntax: TIMES count instruction
    - count can be a number or expression
    - Repeats the following instruction count times
    - Useful for shifts, increments, and buffer allocation

Code Section Examples:
    TIMES 4 SHR R0        ; Shift right 4 times (divide by 16)
    TIMES 8 SHL R1        ; Shift left 8 times (multiply by 256)
    TIMES 3 INC R2        ; Increment 3 times

Data Section Examples:
    buffer:  TIMES 256 DB 0         ; 256 bytes of zeros
    pattern: TIMES 10 DB 0xAA       ; 10 bytes of 0xAA
    mixed:   TIMES 4 DB 0xFF, 0x00  ; Repeats pair: FF 00 FF 00 FF 00 FF 00

ORG Example (.data):
    section .data
    ORG 0x4010
    sprite_data: TIMES 128 DB 0

DATA DIRECTIVES
---------------

DB (Define Byte)
    - Used in .data section
    - Can contain numbers (decimal/hex) or strings
    - Strings are double-quoted: "hello"
    - Escape sequences: \n \t \r \\ \" \0
    - Multiple values separated by commas

Examples:
    msg: DB "Hello World\0"
    values: DB 1, 2, 3, 0xFF
    mixed: DB "A", 65, 0x41

ENCODING
--------

- Every instruction is exactly 3 bytes
- Unused operands are encoded as 0x00
- Format: opcode arg1 arg2
- 16-bit immediates (JMP/JZ/JNZ) are big-endian: [high byte][low byte]
- DB directive bytes are written directly to data section

INSTRUCTIONS
------------

LOADI R, imm8
    -> opcode reg imm8
    -> imm8 can be a number, symbol, or expression (must evaluate to 0..255)

LOAD R, [PAIR]
STORE R, [PAIR]
    -> opcode arg1 arg2
    -> arg1 encodes: REG(7-5) | MODE(4-3) | PAIR(2-1) | 0
    -> arg2 is signed offset for OFFSET mode (two's complement), otherwise 0

    Register Pairs (PAIR field):
      0 = R0:R1
      1 = R2:R3
      2 = R4:R5
      3 = R6:R7

    Addressing Modes (MODE field):
      0 = BASE:   [PAIR]           - direct addressing
      1 = INC:    [PAIR]+          - post-increment
      2 = DEC:    [PAIR]-          - post-decrement
      3 = OFFSET: [PAIR +/- imm8]  - base + signed offset (-128 to +127)

    Examples:
      LOAD  R0, [R6:R7]        -> 0x11 0xC6 0x00  (reg=0, mode=0, pair=3)
      STORE R1, [R2:R3]+       -> 0x12 0x2A 0x00  (reg=1, mode=1, pair=1)
      LOAD  R3, [R4:R5 + 10]   -> 0x11 0x7C 0x0A  (reg=3, mode=3, pair=2, offset=10)
      LOAD  R0, [R2:R3 - 5]    -> 0x11 0x0E 0xFB  (reg=0, mode=3, pair=1, offset=-5=0xFB)

MOV R1, R2
ADD R1, R2
SUB R1, R2
ADC R1, R2
SBC R1, R2
AND R1, R2
OR  R1, R2
XOR R1, R2
CMP R1, R2
    -> opcode R1 R2

INC R
DEC R
SHL R
SHR R
    -> opcode R 0

PUSH R
POP R
    -> opcode R 0

MOVSPR PAIR
    -> opcode pair_id 0
    -> Move stack pointer to register pair (PAIR = SP)
    -> pair_id: 0=R0:R1, 1=R2:R3, 2=R4:R5, 3=R6:R7

MOVRSP PAIR
    -> opcode pair_id 0
    -> Move register pair to stack pointer (SP = PAIR)
    -> pair_id: 0=R0:R1, 1=R2:R3, 2=R4:R5, 3=R6:R7

JMP addr16 | label
JZ  addr16 | label
JNZ addr16 | label
JC  addr16 | label
JNC addr16 | label
    -> opcode hi lo
    -> addr16 can be a number, label, or expression (must evaluate to 0..65535)

CALL addr16 | label
    -> opcode hi lo
    -> pushes return address and jumps to subroutine
    -> addr16 can be a number, label, or expression (must evaluate to 0..65535)

RET
    -> opcode 0 0
    -> pops return address and returns from subroutine

HALT
    -> opcode 0 0

DB value1, value2, ...
    -> (data section only)
    -> writes bytes directly to data section

ASSEMBLY PASSES
---------------

Pass 0 (Preprocessing):
- Expand .macro definitions
- Process .include directives
- Replace macro invocations with expanded body
- Generate unique labels for local labels (@label)

Pass 1:
- Remove comments
- Track section directives
- Collect symbols (labels and constants)
- Compute instruction addresses (code at 0x0010+, data at 0x4000+)
- Handle ORG in .data by advancing the data location counter and padding with zeros as needed
- Parse TIMES prefix and multiply instruction count accordingly
- Parse DB directives and accumulate data bytes

Pass 2:
- Encode instructions in code section
- Handle TIMES by emitting instruction multiple times
- Resolve symbols to values
- Emit bytecode
- Output file signature (16 bytes)
- Output code section
- Pad to data section boundary (0x4000)
- Output data section if present

ERRORS
------

Assembly fails on:
- Unknown instruction
- Invalid register
- Invalid number
- Immediate out of range
- Undefined or duplicate label/constant
- TIMES with invalid count
- ORG used outside .data
- ORG address out of range
- ORG that rewinds data (address < current data location counter)
- Expression errors (division by zero, undefined symbols, syntax errors)

OUTPUT
------

Binary file with the following structure:

File Signature (16 bytes at 0x0000-0x000F):
- Bytes 0-3:   Magic number ('T', '1', '6', 0x00)
- Bytes 4-5:   Version (major, minor)
- Bytes 6-7:   Entrypoint address (big-endian, typically 0x0010)
- Bytes 8-15:  Reserved (zeros)

Code Section (starts at 0x0010):
- Instructions encoded as 3-byte sequences
- Ends at 0x3FFF (max ~16KB)

Data Section (starts at 0x4000):
- Padded with zeros from end of code to 0x4000
- DB directives output here
- Can extend to 0x923F to initialize graphics memory:
  - 0x4000-0x4FFF: User data (4KB)
  - 0x5000-0x6FFF: Tile data (8KB, 256 tiles × 32 bytes)
  - 0x7000-0x8FFF: Tilemap (8KB, 128×32 tiles, 2 bytes each: tile + attr)
  - 0x9000-0x91FF: OAM (512 bytes, 128 sprites × 4 bytes)
  - 0x9200-0x923F: Palette (64 bytes, 4 palettes × 16 colors)

EXAMPLES
--------

Basic program with sections:

    section .code

    LOADI R0, 42
    HALT

    section .data

    value: DB 255

Subroutine example:

    section .code

    START:
        LOADI R0, 5
        LOADI R1, 3
        CALL  ADD_FN
        HALT

    ADD_FN:
        ADD   R0, R1
        RET

Using TIMES for efficient shifts:

    section .code

    START:
        LOADI R0, 128
        TIMES 4 SHR R0    ; R0 = 128 >> 4 = 8 (divide by 16)
        HALT

Defining graphics data directly:

    section .data

    ; User data at 0x4000
    ORG 0x4000
    state: DB 0

    ; Define an 8x8 tile (32 bytes)
    ORG 0x5000
    tile0: DB 0x01, 0x11, 0x11, 0x10  ; Row 0
           DB 0x12, 0x22, 0x22, 0x21  ; Row 1
           ; ... remaining rows ...

    ; Pad to OAM at 0x9000
    ORG 0x9000

    ; Initialize all 128 sprites as hidden (Y = 0xFF)
    oam:   TIMES 128 DB 0xFF, 0x00, 0x00, 0x00

    ; Palette at 0x9200 (palette slot 0)
    palette:
           ORG 0x9200
           DB 0x03  ; Color 0: dark blue (RGB332)
           DB 0x1F  ; Color 1: blue
           DB 0xFC  ; Color 2: yellow
           DB 0x00  ; Color 3: black

String data:

    section .data

    msg:    DB "Hello World\0"
    count:  DB 12

Mixed data types:

    section .data

    header: DB 0xFF, 0xFE, "ID"
    values: DB 1, 2, 3, 4

Using expressions:

    TILE_SIZE = 8
    TILE_BYTES = TILE_SIZE * TILE_SIZE / 2  ; 32
    DATA_ADDR = 0x4020

    section .code
    LOADI R0, (5 + 3) * 2           ; R0 = 16 (expression in immediate)
    LOADI R6, DATA_ADDR >> 8        ; R6 = 0x40 (high byte)
    LOADI R7, DATA_ADDR & 0xFF      ; R7 = 0x20 (low byte)
    JMP start + 12                  ; Expression in jump target

    section .data
    ORG 0x4000 + 256                ; Expression in ORG
    buffer: TIMES TILE_SIZE * 4 DB 0  ; Expression in TIMES

NON-GOALS
---------

- No macros
- No includes
- No linking or relocation
- No conditional assembly
- No string manipulation or concatenation

DESIGN RULE
-----------

- The assembler performs no semantic analysis.
- It translates text to bytes exactly as defined by the tiny16 ISA.
